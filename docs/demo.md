# 前端演示脚本

一条从登录页走到退出登录的完整演示路径，约 5 分钟。演示前先把后端仓库启动起来。

## 一、前置条件

后端（另一个仓库）已启动并能访问 `http://localhost:8000/health`：

```bash
cd intern-day-2-backend
docker compose up --build -d
docker compose exec api uv run python -m app.seed
```

练习账号：`demo` / `demo12345`。

## 二、启动前端

```bash
docker compose up --build -d
# 或者用开发服务器
pnpm install && pnpm dev
```

浏览器打开 `http://localhost:5173`。
地址统一用 `localhost`，不要与 `127.0.0.1` 混用，否则后端 CORS 白名单对不上。

## 三、演示步骤

### 1. 登录

1. 先故意输错密码 → 停在登录页，红字提示「账号或密码错误」，这条文案来自后端。
2. 账号或密码留空直接提交 → 前端拦截，提示「请填写账号和密码」，不发请求。
3. 连点两次登录按钮 → 按钮进入加载态并禁用，只发出一次请求。
4. 输入 `demo` / `demo12345` → 进入 `/memo`，右上角显示后端返回的 `display_name`（练习同学）。

### 2. 备忘录页

1. 输入一件事，填截止时间，例如 `交第二天总结` / `2026-11-27T18:00`。
2. **标签分两行，两行都必须各选一个**：
   - 第一行「重要性」：`重要`（深红实心）/ `不重要`（淡红）
   - 第二行「紧迫性」：`紧急`（实心琥珀）/ `不紧急`（淡琥珀）
3. 只选第一行就提交 → 提示「第二行还没选：这件事紧急吗？」；只选第二行 → 提示「第一行还没选：这件事重要吗？」。
4. 两行都选好后提交 → 列表出现新条目，标签按 `重要 · 紧急` 等顺序显示。
5. **点左侧圆点** → 圆点变实心打勾，标题加删除线；刷新页面，划掉状态仍在（已写入后端）。
6. **长按某一行约 0.3 秒再上下拖动** → 出现插入位置的横线，松手后顺序变化；刷新后顺序保持。
   不按够时间就松手只是普通点击，不会误触排序。
7. 点删除 → 条目消失。

### 3. 四象限页

1. 切到 `/matrix`：左侧是「待分类」池，右侧四个格子。
2. 把一张卡片拖进「重要 · 不紧急」→ 卡片落格，标签随之变成「不紧急」「重要」。
3. 回备忘录页 → 同一条目的标签已经同步更新。
4. 在四象限页点卡片上的「移出」→ 回到待分类池，标签变「未分类」。

### 4. 登录态

1. 已登录状态下刷新页面 → 前端用本地令牌向 `/auth/me` 复验，通过后留在原页，不会莫名退回登录页。
2. 未登录直接访问 `/memo` → 被路由守卫送回 `/login`，受保护内容不渲染。
3. 点右上角「退出」→ 回登录页；此时用退出前的令牌调后端接口会返回 `401`。

### 5. 异常分支

停掉后端容器，再点任意操作 → 提示「连不上后端服务，请确认后端已启动」；重新启动后端后可继续操作。

## 四、验证清单

| 检查项 | 预期 |
| --- | --- |
| `pnpm run typecheck` | 0 错误 |
| `pnpm run build` | 39 modules，构建成功 |
| 错误密码 | 停留在登录页并提示 |
| 标签两行都必选 | 缺一行会被拦下并给出对应提示 |
| 划掉 / 排序 / 拖拽 | 刷新后状态仍然保持 |
| 登录态失效 | 接口返回 `401` 时自动回登录页 |
